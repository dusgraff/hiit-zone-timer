# specs

## Scope

Living specs: the authoritative, current design of the app and of how the project is run. Start from README.md for the overview and reading order. The reasoning behind decisions lives in [specs-ADRs/](../specs-ADRs/.tldr.md), not here. Claude owns the layout of this folder.

## Contents

- [README.md](README.md) — entry point: project overview and the reading order for all specs.
- [adr-structure.md](adr-structure.md) — ADR folders, ID naming and dating, lifecycle, link rules.
- [adr-process.md](adr-process.md) — how decisions are made: 8 steps, statuses, who does what, supersession, loose ends, ADR template, specs structure.
- [app-architecture.md](app-architecture.md) — app design below the workout level: hosting (GitHub Pages, docs/), single page and hash navigation, ES modules, screens/menu/guided flow, look (navy/yellow color scheme), Bluetooth and reconnect, wake lock, foreground-only, pre-programmed data and no storage, prototype pages.
- [profiles.md](profiles.md) — heart rate zones 0–5 and the three fixed fitness profiles' bpm tables (no age input); profile usage rules.
- [workouts.md](workouts.md) — running a workout: HR-gated phase timers, zone targets, the nine workouts (Demo, Moderate/Hard × 5–20 min), Select workout redirects, running workout screen and progress bar, sounds/vibration/alarm rules, leaving mid-way, no-reading handling.
